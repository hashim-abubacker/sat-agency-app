# Project Architecture v2.0
## Simple Agency Tool

---

# Purpose

Projects are the primary workspace inside Simple Agency Tool.

Every piece of work performed for a client is represented as an independent project.

Examples:

- Website Development
- Monthly Social Media
- SEO
- Branding
- Product Photography
- Video Production
- Google Ads
- Marketing Campaign

A client may own unlimited projects.

Each project operates independently.

---

# Design Philosophy

Projects should remain lightweight.

The interface should only display tools that are actually required for the selected project.

The application should never overwhelm users with features they don't need.

Additional functionality should be enabled only when necessary.

# Why a Checkbox?

Content planning is only required for marketing projects.

Website projects

Branding

Photography

Video Editing

Consulting

Research

do not always require content scheduling.

Instead of forcing every project to include unnecessary features, Content Planner is enabled only when required.

This keeps the interface clean.

# Content Planner

The Content Planner is **not** a social media management platform.

It is simply a planning tool.

Purpose

Allow agencies to schedule future content.

Examples

Instagram Posts

Instagram Reels

Facebook Posts

Stories

LinkedIn Posts

YouTube Videos

Blogs

Emails

The planner exists only to answer one question:

"What content needs to be published and when?"

---

# Content Planner Scope

Version 1 intentionally excludes

❌ Social media publishing

❌ API integrations

❌ Analytics

❌ Comments

❌ Approval workflows

❌ AI caption generation

❌ Performance reports

❌ Auto-posting

The Content Planner is only a planning calendar.

---

# Relationship with Tasks

Content Planner does not replace Tasks.

Example

```
Instagram Reel

↓

Tasks

Write Script

↓

Record Video

↓

Edit Video

↓

Design Thumbnail

↓

Review

↓

Publish
```

Tasks track production.

Content Planner tracks publication.

These are different concepts.

# Relationship with Calendar

Global Calendar

# User Experience Principles

The feature should remain intentionally lightweight.

Rules

Do not become another ClickUp.

Do not become another Hootsuite.

Do not become another Buffer.

Keep the workflow focused.

Every content item should be creatable in under one minute.

---

# Future Expansion

Future versions may include

- Client approval
- Social media API integration
- Auto publishing
- Analytics
- AI caption suggestions
- Hashtag suggestions
- Performance reports
- Campaign planning
- Content templates

None of these should affect Version 1.

---

# Design Principles

Projects are the primary workspace.

Clients own projects.

Content Planner is an optional project capability.

The global Calendar remains dedicated to operational scheduling.

The Content tab should only appear when enabled.

Simple workflows are preferred over feature-rich workflows.

Every feature must justify its complexity.

The application should remain calm, minimal, and easy to learn.
